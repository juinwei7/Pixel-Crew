# SDD：官方像素角色與自訂角色切換

## 1. 目標

在既有角色工坊加入「官方角色」與「自訂上傳」兩種來源。使用者能替每位 NPC 選擇內建、可動畫的官方角色，也能保留並重新啟用已上傳的 PNG／GIF，不因切換官方角色而遺失自訂檔案。

## 2. 使用者體驗

- 角色工坊頂部提供清楚的分段標籤：`官方角色`、`自訂上傳`。
- 官方角色以角色卡呈現名稱、定位、色彩與像素預覽；目前套用的角色有明確選取狀態。
- 點選卡片只更新預覽，按「套用角色」後才保存，避免誤觸立即改變 NPC。
- 自訂頁完整保留現有 PNG／JPEG／WebP 轉像素、GIF 動畫與安全限制。
- 切到官方角色時保留自訂圖片；稍後回到自訂頁可一鍵重新套用，不需再次上傳。
- 舊資料相容：有 `avatar_id` 的 NPC 視為自訂角色；沒有的 NPC 使用 `classic` 官方角色。

## 3. 官方角色目錄

首版提供五名角色，全部沿用既有前、後、側面、走路、工作與歡呼動畫：

| ID | 顯示名稱 | 視覺定位 |
| --- | --- | --- |
| `classic` | 經典隊員 | 延續 NPC 原本依序分配的制服色 |
| `cyber` | 霓虹工程師 | 青藍制服、深藍髮色 |
| `signal` | 訊號分析師 | 紫色制服、銀灰髮色 |
| `spark` | 火花設計師 | 桃紅制服、暖棕髮色 |
| `ops` | 夜班維運 | 金橘制服、黑藍髮色 |

角色目錄是程式內建的固定清單，不從使用者輸入產生；前後端以同一組 ID 契約驗證。

## 4. 資料模型

`workers` 新增：

- `avatar_kind`: `preset | custom`，表示目前啟用來源。
- `avatar_preset_id`: 官方角色 ID，預設 `classic`。
- `avatar_id`: 保留既有自訂圖片 ID；切換官方角色時不刪除。

伺服器輸出的 Worker summary 與前端 `WorkerState` 同步新增 `avatarKind`、`avatarPresetId`。

## 5. API

- `PUT /api/workers/:id/avatar`
  - 維持上傳行為，成功後將 `avatar_kind` 設為 `custom`。
- `PUT /api/workers/:id/avatar-preset`
  - Body：`{ presetId }`
  - 驗證 ID 後設為目前官方角色，不刪除 `avatar_id`。
- `POST /api/workers/:id/avatar/custom`
  - 重新啟用既有自訂圖片；沒有自訂圖片時回傳 409。
- `DELETE /api/workers/:id/avatar`
  - 明確刪除自訂圖片並回到 `classic`，只供自訂頁「刪除自訂角色」使用。

## 6. 畫面與動畫

- 官方角色直接由像素 map 與 palette 產生，避免縮放模糊並維持所有方向動畫。
- `Person` 可在不重建場景的情況下重新建立官方貼圖；舊貼圖立即釋放。
- 自訂來源啟用時載入既有 PNG／GIF；官方來源啟用時不請求自訂檔案。
- 切換完成由既有 WebSocket `worker_updated` 即時同步所有開啟頁面。

## 7. 邊界與失敗處理

- 未知官方 ID 回傳 400，前端顯示原因。
- 自訂檔案遺失或解碼失敗時，場景回退目前官方角色並顯示錯誤，不留下透明 NPC。
- DB 寫入失敗時回滾記憶體狀態。
- 舊資料庫 migration 可重複執行，不改動既有自訂檔案。

## 8. 驗收條件

1. 新舊資料庫皆能啟動；舊自訂角色仍顯示。
2. 角色工坊可在兩個標籤間切換，官方角色卡有可辨識預覽與選取狀態。
3. 五個官方角色可保存並立即反映在場景，走路、工作、歡呼動畫正常。
4. 上傳 PNG／GIF 後自動切到自訂來源；切官方再切回自訂不需重傳。
5. 刪除自訂角色後回到 `classic`，本機孤立檔案會清理。
6. 未知 preset、無自訂檔案卻要求啟用 custom，會收到可讀錯誤。
7. Server tests、Web tests、兩端 production build 全部通過。
