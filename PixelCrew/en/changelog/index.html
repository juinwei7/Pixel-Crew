NEW RELEASE · 2.3.1

Remote access connects, and terminals stay steadier.

Version 2.3.1 fixes the blank remote screen in source development by keeping the UI, API, and WebSocket behind one authenticated origin. It also hardens Black Window terminal lifecycles, responsive interaction, and accessibility.

v2.3.1 2026.09.09 View full release notes ↗
01 / REMOTE ACCESSSource development no longer opens to a blank screen

The gateway detects production and Vite development UIs, sends the page to the right service, and keeps API and application WebSocket traffic on the core server.

02 / SAME ORIGINA phone no longer connects to its own localhost

Remote browsers use the tunnel origin for API and WebSocket requests, preserving the login cookie and gateway protection throughout the session.

03 / GATEWAY SAFETYThe development server's filesystem route is closed

The remote gateway rejects Vite's /@fs/ path so an authenticated request cannot bypass application routes to read workspace files.

04 / TERMINAL LIFECYCLEBlack Window better survives reloads and interruptions

Daemon-backed terminal startup, recovery, shutdown, and layout synchronization are hardened to reduce disconnected terminals and unreachable processes.

05 / RESPONSIVE + A11YNarrow screens, keyboards, and screen readers behave consistently

Workbench surfaces, tool dialogs, and composers now have more complete responsive behavior, focus semantics, and keyboard interaction across phone and desktop layouts.

06 / CROSS-PLATFORMPTY coverage better matches Windows behavior

ConPTY sizing and delayed-cleanup tests are stabilized so terminal lifecycle behavior remains covered across macOS, Linux, and Windows CI.
